# Full SEO Audit Report — Tanzania Sensational

**Date:** 2026-05-08 (Updated from previous audit)
**Auditor:** SEO Lead  
**Site:** tanzaniasensational.com  
**Stack:** Laravel 11 (API) + React 18 SPA (CSR) + Vite 7 + SQLite (dev) / MySQL (prod)

---

## Executive Summary

This is a **re-audit** following significant improvements made in Sessions 1-3 (sitemap expansion, robots.txt, HTTPS redirect, Organization schema, H1 fixes, database migration). The site now has a solid technical foundation — server-rendered meta tags, dynamic sitemap with priority/changefreq/lastmod, expanded JSON-LD schema, and a well-structured content model.

**However, several critical issues remain:**

1. **Pure CSR SPA** — All content loads via JavaScript after API calls. Google's second-pass rendering may not execute all JS, especially for deeply nested routes. This is the #1 reason organic traffic is ~10/mo.
2. **16 trekking route variations have NULL meta_title and meta_description** — These are the highest-value commercial pages on the site, yet they fall back to auto-generated titles.
3. **All 12 blog posts have ~950 chars of placeholder content** — Thin, generic content that Google's helpful content system will devalue.
4. **SafariPackage and Destination models lack dedicated `meta_title`/`meta_description` columns** — They rely on a single `meta_tag` field, which is insufficient for SERP optimization.
5. **No hreflang tags** despite targeting 12+ countries.
6. **Newsletter form has no backend** — No email capture capability.

**Estimated organic traffic impact if all Critical/High issues are fixed:** 5-10x increase within 6 months (from ~10/mo to 50-100/mo), assuming content investment.

## 1. TECHNICAL SEO

### 1.1 CRITICAL: CSR-Only Rendering (Indexability Risk)

| Issue | Severity | Details |
|-------|----------|---------|
| Pure CSR SPA | **CRITICAL** | The site uses `ReactDOM.createRoot()` on a minimal Blade shell. All content is loaded via API calls after JS execution. Google's rendering queue may not execute all JS, especially for pages requiring API data. |

**Evidence:**
- [`resources/js/main.jsx`](resources/js/main.jsx:11) — `ReactDOM.createRoot(document.getElementById('root')).render(...)` — pure CSR mount
- [`resources/views/app.blade.php`](resources/views/app.blade.php:36) — only `<div id="root"></div>` in body
- All page components (e.g., [`Lemosho.jsx`](resources/js/pages/trekking/kilimanjaro/Lemosho.jsx:23-41)) fetch data via `useEffect` → API calls
- [`SafarisPage.jsx`](resources/js/pages/SafarisPage.jsx:47-50) — loads destinations via `destinationService.getAll()` in `useEffect`

**Impact:** Google may index only the default meta tags and an empty shell for pages where JS fails to execute or API calls time out. This is the #1 reason this site has only ~10 monthly organic visits.

**Recommendation:** Implement SSR (via Laravel + Inertia.js, or a lightweight prerendering service like Prerender.io). At minimum, add server-side rendered fallback content for critical pages.

## 6. PAGE SPEED (CORE WEB VITALS)

### 6.1 ✅ RESOLVED: Google Fonts Loading Optimized (Async + Preload)

| Issue | Severity | Status |
|-------|----------|--------|
| Render-blocking fonts | **MEDIUM** | **✅ RESOLVED** — Fonts now load asynchronously with preload for critical discovery |

**What changed:** [`resources/views/app.blade.php`](resources/views/app.blade.php:21-28):
1. **Replaced Inter with DM Sans** — Inter was barely used in the CSS; DM Sans is the `--font-label` variable and actually renders on every page
2. **Added preload link** — `<link rel="preload" ... as="style" crossorigin="anonymous">` tells the browser to discover the font stylesheet early
3. **Async loading pattern** — Changed to `media="print" onload="this.media='all'"` — the stylesheet loads without blocking rendering, then switches to `all` media after load
4. **Noscript fallback** — Ensures fonts still load for users without JavaScript

**Before:** Synchronous `<link rel="stylesheet">` — blocked rendering until fonts downloaded
**After:** Preload + async stylesheet — fonts discovered early but don't block rendering

**Why:** Synchronous font loading is a major contributor to poor LCP. The `media="print" onload="this.media='all'"` pattern makes font loading non-render-blocking while preload ensures the browser discovers the font early. Replacing Inter with DM Sans eliminates a wasted font download (Inter was imported but barely used in the CSS).
